## 2. Required exact-head checks

- Migration preflight: all migration filenames ordered, no duplicate identifiers or unexplained gaps, 042 catalog-equivalence accepted only under its pinned legacy checksum, and 040-to-044 alias only when hashes match.
- Migration runner: target must be the explicitly confirmed Preview/test database, direct connection only, role neondb_owner, transaction per migration, exact SHA-256 recorded with the SQL change.
- Database proof: non-PostGIS public tables must have FORCE RLS, spatial_ref_sys must be read-only for the runtime role, schema_migrations must have FORCE RLS and zero runtime privileges.
- Identity: NOBYPASSRLS runtime tests, no-context denial, tenant-scoped reads, cross-tenant insert/update denial.
- Future tables: a transaction-scoped scratch relation receives CRUD-like runtime privileges as a default-ACL simulation and must still enforce FORCE RLS and restrictive tenant policies. Test must roll back.
- Password reset: verify SECURITY DEFINER, pinned search_path, row_security=off, active owner/admin actor, active target user, expiry strictly less than 30 minutes, and rejection of expired/overlong tokens. The test-owner's lack of BYPASSRLS must not be confused with proof of production definer behavior.
- Package: release files are sanitized, package manifest exact, no nested archives/runtime user data, ZIP round-trip passes, and same-pipeline attestation/checksums match.
- Vercel: deploy Preview only after same-pipeline archive identity check; then smoke-test all public candidate routes and machine-readable proof APIs.
