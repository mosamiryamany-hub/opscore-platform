# OpsCore v0.11.56 — المميزات الجوهرية ذات القيمة التشغيلية

## معيار الاختيار

لا تُعتبر الميزة ذات قيمة لمجرد وجودها في الواجهة أو قاعدة البيانات. الميزة الجوهرية هنا هي التي تفعل واحدًا على الأقل من الآتي:

1. تمنع خطأً يمكن أن يفسد العملية أو البيانات.
2. تمنع تكرار التنفيذ عند إعادة الطلب أو انقطاع الاتصال.
3. تختصر وقت البحث، أو إعادة الشرح، أو المراجعة.
4. تجعل سبب القرار أو الرفض واضحًا بدل الجدال الشفهي.
5. تنتج دليلًا يمكن الرجوع إليه عند النزاع أو التدقيق.
6. تقلل كمية العمل اليدوي التي يحتاجها الموظف أو المطور.

## 1. عزل المؤسسات والصلاحيات

**القيمة:** يمنع وصول مؤسسة إلى بيانات مؤسسة أخرى، ويجعل الصلاحيات مرتبطة بسياق المستخدم والمؤسسة بدل الاعتماد على الواجهة فقط.

**ما يختصره:** إعادة بناء طبقات العزل والصلاحيات لكل شاشة وواجهة API.

**ما يمنعه:** تسرب بيانات بين المستأجرين، أو منح مفتاح قراءة قدرة كتابة.

**الدليل:** اختبارات عزل متعددة المؤسسات واختبارات صلاحيات API ضمن حزمة الاختبارات.

---

## 2. Idempotency للعمليات الحساسة

**القيمة:** الطلب المكرر لا يعيد الأثر الجانبي مرة ثانية؛ والطلب نفسه لا يمكن إعادة استخدام مفتاحه مع Payload مختلف.

**ما يختصره:** معالجة مشاكل الضغط المزدوج، إعادة المحاولة، ضعف الشبكة، أو تكرار الطلبات من العميل.

**ما يمنعه:** إنشاء موعد مرتين، تسجيل إجراء مرتين، تكرار استهلاك أو حجز مادة، أو تكرار توقيع العميل.

**الدليل:** اختبارات replay ورفض إعادة استخدام المفتاح مع بيانات مختلفة.

---

## 3. مزامنة Offline مع عزل الفشل

**القيمة:** فشل حدث واحد لا يلغي أحداثًا صحيحة مجاورة. الأحداث القابلة لإعادة المحاولة تبقى معلقة، والأخطاء النهائية تُعزل صراحةً.

**ما يختصره:** إعادة إدخال العمليات يدويًا بعد انقطاع الإنترنت.

**ما يمنعه:** فقد سلسلة كاملة من الإجراءات بسبب عنصر واحد غير صالح.

**الدليل:** اختبار valid → invalid → valid واختبارات حالات applied / duplicate / failed.

**الحد:** مزامنة الأدلة غير المتصلة مدعومة في مسار محدد، ولا يُعلن عن أي دليل كـ"مُسلَّم" حتى يقبله الخادم.

---

## 4. إغلاق المهمة بشروط قابلة للتحقق

**القيمة:** لا يكفي تغيير الحالة إلى Completed؛ يمكن أن تفرض المؤسسة متطلبات مثل الدليل، توقيع العميل، السلامة، أو إكمال الإجراء.

**ما يختصره:** مراجعات ما بعد التنفيذ ورسائل "المهمة اتقفلت لكن ناقصها...".

**ما يمنعه:** إغلاق مهام غير مكتملة أو غير موثقة.

**الدليل:** completion assurance واختبارات حظر الإغلاق غير المستوفي للشروط.

---

## 5. سير عمل محكوم ومُسجّل

**القيمة:** انتقال الحالة يُفحص وفق Workflow فعّال قبل الحفظ، وليس مجرد زر يسمح بتغيير الحالة.

**ما يختصره:** النقاش المتكرر حول "من حقه يغير الحالة؟ وما المسار الصحيح؟".

**ما يمنعه:** انتقالات غير مسموحة أو تجاوز خطوات تشغيلية مقصودة.

**الدليل:** اختبارات فرض الـWorkflow وتسجيل إصدار السياسة والمنفذ والسبب وبصمة القرار.

---

## 6. حزمة أدلة موحدة للعمل

**القيمة:** تجمع حالة أمر العمل، الموعد/الوصول، SLA، الأجزاء، المرفقات، التوقيعات، السلامة، النشاط والتدقيق في حزمة واحدة قابلة للتحقق.

**ما يختصره:** البحث في عدة شاشات وملفات عند المراجعة.

**ما يمنعه:** اختلاف الروايات بسبب الاعتماد على الذاكرة أو محادثات منفصلة.

**الدليل:** فحص SHA-256 للمرفقات وبصمة للحزمة واختبار الاتساق.

**الحد:** آلية سلامة على مستوى التطبيق، وليست شهادة WORM أو اعتمادًا قانونيًا.

---

## 7. سلسلة تدقيق قابلة للتحقق

**القيمة:** السجل لا يقتصر على "من فعل ماذا"؛ يمكن إعادة حساب السلسلة واكتشاف تعديل غير متوافق معها.

**ما يختصره:** التحقيق اليدوي في تاريخ تغييرات مهمة.

**ما يمنعه:** العبث الصامت بالسجل على مستوى التطبيق.

**الدليل:** endpoint تحقق read-only واختبار يكشف التلاعب بالسلسلة.

**الحد:** ليست شهادة عدم قابلية المحو قانونيًا أو تخزين WORM خارجيًا.

---

## 8. Check-in جغرافي مرتبط بالمهمة والفني

**القيمة:** الخادم هو الذي يتحقق من أن المستخدم هو الفني المعني وأن نقطة الوصول تقع ضمن الحدود المسموح بها للموقع.

**ما يختصره:** الجدال حول "هل الفني وصل فعلًا؟" عند توفر الإحداثيات المقبولة.

**ما يمنعه:** ربط check-in بمهمة أخرى أو بمستخدم من مؤسسة أخرى.

**الدليل:** اختبارات actor binding والعزل الجغرافي وسياق المهمة.

---

## 9. توزيع المواعيد مع حماية التعارض

**القيمة:** النظام يتحقق من تعارض مواعيد الفني، ويدخل المهارات في اختيار المرشحين.

**ما يختصره:** البحث اليدوي داخل جداول ومحادثات الفريق.

**ما يمنعه:** تكليف فني بموعدين متعارضين أو تجاهل مهارة مطلوبة.

**الدليل:** اختبارات scheduling conflict وskill filtering.

**الحد:** الحساب الجغرافي للمسافة ليس محرك توجيه مروري.

---

## 10. المخزون محمي من الرصيد السالب

**القيمة:** الحجز والاستهلاك يراعيان الرصيد المتاح ويمنعان النزول إلى مخزون سالب.

**ما يختصره:** مراجعة يدوية لاكتشاف حركات مخزون غير منطقية.

**ما يمنعه:** صرف كمية غير متاحة وتضارب الأرقام بين المخزون والعمل المنفذ.

**الدليل:** اختبارات reservation/consumption وnegative-stock protection.

---

## 11. استيراد العملاء على مرحلتين

**القيمة:** Dry-run يفحص البيانات قبل الكتابة، والاستيراد الفعلي الذري لا يترك نصف العملية مكتوبًا.

**ما يختصره:** إصلاح ملفات الاستيراد بعد حدوث أخطاء جزئية في قاعدة البيانات.

**ما يمنعه:** إدخال بيانات غير صالحة أو حالة بيانات نصف مستوردة.

**الدليل:** اختبارات dry-run وatomic import.

---

## 12. بوابة عميل ذات نطاق مستقل

**القيمة:** وصول العميل منفصل عن جلسات الموظفين ومحصور ببياناته.

**ما يختصره:** تحويل كل استفسار عميل إلى تدخل يدوي من موظف الدعم.

**ما يمنعه:** وصول العميل إلى بيانات خارج نطاقه.

**الدليل:** اختبار bootstrap والتدوير إلى جلسة scoped واختبارات العزل.

---

## 13. تسليم المهمة Handoff كحزمة واحدة

**القيمة:** عند انتقال المسؤولية، يحصل الموظف التالي على الحالة الحالية، الإجراء التالي، الخطر، الموعد، العوائق، الأدلة، آخر ملاحظة، والأحداث الأخيرة.

**ما يختصره:** مكالمات الشرح المتكررة وإعادة بناء قصة المهمة.

**ما يمنعه:** فقدان السياق عند انتقال المهمة بين الموظفين.

**الدليل:** endpoint handoff read-only ومحدد بنطاق المؤسسة.

---

## 14. Cockpit يركز على العمل الفعلي

**القيمة:** نقطة البداية اليومية تجمع التركيز المحفوظ، العمل المسند، المواعيد، التنبيهات وقرارات الإدارة.

**ما يختصره:** التنقل بين شاشات كثيرة لمجرد معرفة "ما الذي يحتاجه اهتمامي الآن؟".

**ما يمنعه:** إعطاء المتصفح سلطة اختراع مهام جديدة؛ القرار التشغيلي الأساسي مصدره الخادم.

**الدليل:** cockpit API واختبارات عدم توليد عمل اصطناعي.

---

## 15. مخاطر تشغيلية حتمية وقابلة للتفسير

**القيمة:** يبرز المهام المتأخرة أو المحجوبة أو العاجلة أو غير المسندة أو المعرضة لخطر SLA وفق بيانات محفوظة فعليًا.

**ما يختصره:** الفرز اليدوي اليومي لقائمة طويلة من المهام.

**ما يمنعه:** ادعاء تنبؤ أو "ذكاء" مبني على بيانات غير موجودة.

**الدليل:** اختبارات deterministic risk وdaily operations brief.

**الحد:** ليس نظام AI تنبؤيًا أو autonomous decision engine.

---

## 16. مفتاح API بنطاقات وصلاحيات محددة

**القيمة:** التكامل البرمجي يمكن أن يحصل على أقل قدر لازم من الصلاحيات بدل مفتاح واحد شامل.

**ما يختصره:** إعادة بناء طبقة وصول منفصلة لكل تكامل.

**ما يمنعه:** تحويل مفتاح قراءة إلى قناة كتابة غير مقصودة.

**الدليل:** اختبارات رفض عمليات الكتابة لمفتاح read-only.

---

## 17. Webhook مُوقّع ومحمي من SSRF

**القيمة:** التحقق من عنوان الهدف وتوقيع الرسائل HMAC-SHA-256 قبل التسليم.

**ما يختصره:** بناء طبقة أمان منفصلة لكل Webhook.

**ما يمنعه:** تسليم إلى أهداف غير مسموحة وتزوير الرسائل القادمة من التكامل.

**الدليل:** اختبارات SSRF وتوقيع Webhook وتشفير السر المخزن.

---

## 18. فحص توافق إصدار الموبايل وفشل مغلق

**القيمة:** العميل غير المدعوم لا يستمر بصمت على عقد API غير متوافق.

**ما يختصره:** تشخيص أخطاء غامضة ناتجة عن عدم توافق التطبيق والخادم.

**ما يمنعه:** استمرار عميل قديم في إرسال عمليات غير مفهومة للخادم.

**الدليل:** اختبار compatibility gate وfail-closed.

---

## 19. تصدير المؤسسة مع استبعاد الأسرار وبصمة للنسخة

**القيمة:** نقل بيانات المؤسسة يتم من خلال export معروف البنية مع استبعاد بيانات الاعتماد وإضافة SHA-256 للـsnapshot.

**ما يختصره:** إعداد نقل أو تسليم بيانات الاستحواذ يدويًا.

**ما يمنعه:** تسرب كلمات المرور والجلسات ومفاتيح API أثناء التصدير المقصود للبيانات التشغيلية.

**الدليل:** اختبار tenant-scoping وcredential exclusion وsnapshot hash.

---

## 20. Recovery Drill قابل للتنفيذ

**القيمة:** لا يكتفي بوجود سكربت backup؛ توجد تجربة استعادة إلى قاعدة منفصلة وفحص سلامة وتطابق بنية/عدد سجلات.

**ما يختصره:** الجدل حول "هل النسخة الاحتياطية قابلة للاستعادة أصلًا؟".

**ما يمنعه:** الثقة العمياء في ملف backup لم يُختبر.

**الدليل:** recovery drill regression.

**الحد:** لا يثبت RPO/RTO إنتاجيًا ولا متانة object storage أو البنية السحابية للمشتري.

---

# ما يجب أن يظهر في صفحة البيع

الأولوية التجارية للمميزات ليست عددها، بل أثرها:

**1. منع التكرار والأخطاء:** Idempotency + Offline failure isolation.

**2. منع الإغلاق الخاطئ:** Completion Assurance + Governed Workflow.

**3. إثبات ما حدث:** Evidence Package + Audit Chain + GPS Check-in.

**4. تقليل وقت المكتب:** Dispatch + Cockpit + Handoff + Operational Brief.

**5. حماية البيانات:** Tenant Isolation + RBAC + API Scopes + Webhook Security.

**6. تقليل مخاطر نقل البيانات والتعافي:** Atomic Import + Verified Export + Recovery Drill.

هذه هي الرسائل ذات القيمة الفعلية. أما عدّ عشرات الشاشات أو الجداول أو المسارات كـ"مميزات" مستقلة فلا يضيف قيمة للمشتري ولا ينبغي أن يكون محور الإعلان.
