# Self-Hosted Runtime (Docker Compose + Caddy)

**Scope:** single-server buyer runtime. Does not modify the hosted Vercel/Neon production path.

## Prerequisites

- Docker Engine 24+ and Compose v2
- 2+ vCPU, 4+ GiB RAM recommended for smoke; size GIS workloads separately
- Secrets generated by the buyer (passwords, HMAC keys)

## Start

```bash
cd backend
cp .env.self-hosted.example .env.self-hosted
# edit secrets
docker compose -f docker-compose.self-hosted.yml up --build -d
curl -fsS http://127.0.0.1/api/health
```

## What this stack does

1. PostGIS-enabled PostgreSQL 18 with least-privilege roles from `docker/postgres-init`
2. One-shot `migrate` service using `apply-postgres-migrations.js`
3. Node app image from `docker/Dockerfile` with `/api/health` healthcheck
4. Caddy 2 reverse proxy (HTTP/HTTPS ports published)

## Explicitly not claimed by this compose file alone

- pgBackRest / independent PITR
- Multi-node HA
- Production TLS certificate automation beyond Caddy defaults
- Mobile store binaries
- Licensed map/telephony providers
- Full buyer handoff attestation

Those remain separate gates.
