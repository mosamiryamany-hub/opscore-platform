# Demo Data Policy — v0.11.61

The release package contains no bundled runtime attachment/demo artifacts. The backend runtime attachment store is `backend/data/files/`. Test suites may create temporary attachment files there when run against the repository, so release packaging must clean and gate this path after verification.

Demo records and demo attachments may be generated by the controlled seed flow when a buyer demonstration is required. They must not be treated as production data.

## Release rule

The release packaging gate is fail-closed: any file under `backend/data/files/` (or the legacy root `data/files/`) blocks packaging. The release package is built only after tests complete, runtime artifacts are removed, and the gate passes.

Run the guarded cleanup from the release root when a test/demo checkout has generated backend attachment artifacts:

```bash
OPSC_DEMO_CLEANUP=CONFIRM node backend/scripts/clean-demo-data.js --confirm
```

The command requires `OPSC_DEMO_CLEANUP=CONFIRM` and refuses to run when `NODE_ENV=production`. It verifies the actual backend runtime path and returns success only after the generated attachment files are gone.

## Verification

Run:

```bash
node scripts/release-artifact-gate.js
```

A clean release must report the backend runtime attachment tree as absent and exit with status 0. An unexpected artifact causes status 1; it is never reported as a clean release.

## Truth boundary

This policy does not claim that an arbitrary deployment has zero demo data. It defines the source-release packaging rule and the guarded cleanup/check used before packaging and production initialization.
